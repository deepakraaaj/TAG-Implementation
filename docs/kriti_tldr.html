What It Is

Kriti Bot is a reusable enterprise AI service. It is built once and reused across projects by changing config artifacts (YAML + JSON + URLs), not rewriting core code.

Core Pipeline
route -> intent -> sql_build -> validate -> execute -> respond
Runtime Endpoints
/chat, /health, /metrics
Reuse Inputs
schema manifest + flow YAML + tenant URL

How It Works (Simple)

  1. User sends query to `/chat`.
  2. Router chooses SQL path or Chat path.
  3. SQL path builds and validates SQL with guardrails, then executes on tenant DB.
  4. Response layer returns concise business output and optional metrics/audit signals.

Efficiency + Cost Snapshot

Typical SQL Request
~850 tokens
Typical Chat Request
~270 tokens
Example Load
1500 req/day

At this load, API-model deployment is usually cheaper than dedicated self-hosted GPU for early/mid scale.

Recommendation: Start with API-model deployment, track real usage via `/metrics`, and move to self-hosted only when sustained volume justifies fixed infra.

Latest Production Hardening (2026-02-24)

Stream Reliability
Terminal result envelope guaranteed on failures
Safe Retries
Idempotency key replay support
Observability
trace_id + stage_timings_ms in result payloads
Write Safety
Role-based mutation authorization (deny by default)

Impact: fewer client hangs on errors, safer write paths, clearer debugging, and better operational confidence for enterprise rollout.

Quality status: hardening suite validated with focused unit coverage before release.

Decision in One Line

Adopt Kriti Bot as a reusable service layer now. It reduces new-domain delivery time and avoids repetitive report/API development while keeping costs measurable.
