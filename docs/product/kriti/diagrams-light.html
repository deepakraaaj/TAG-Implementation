2) Request Sequence Diagram

Runtime interaction from user prompt to response stream.

sequenceDiagram
  participant User
  participant UI as Frontend
  participant API as /chat
  participant Router as RouterNode
  participant Builder as SQLBuilderNode
  participant Validator as SQLValidateNode
  participant Exec as SQLExecuteNode
  participant DB as Database

  User->>UI: Ask question
  UI->>API: POST /chat
  API->>Router: classify SQL or CHAT
  alt SQL path
    Router->>Builder: parse intent + filters
    Builder->>Validator: SQL query
    Validator->>Exec: validated SQL
    Exec->>DB: execute
    DB-->>Exec: rows
    Exec-->>API: row_count + preview
  else CHAT path
    Router-->>API: send to ChatNode
  end
  API-->>UI: NDJSON stream

6) Data Governance & Safety

Guardrails for prompt injection, SQL validation, and tenant scoping.

flowchart TD
  Q[Incoming Query] --> PI{Prompt Injection Detector}
  PI -->|blocked| SAFE_MSG[Safe rejection message]
  PI -->|clean| ROUTE[Route intent]

  ROUTE --> SQLGEN[Build SQL]
  SQLGEN --> VAL{SQL Safety Validator}
  VAL -->|invalid| ERR[Validation failure response]
  VAL -->|valid| RUN[Execute SQL]

  RUN --> RESP[Response Node]
  RESP --> USER[User]
