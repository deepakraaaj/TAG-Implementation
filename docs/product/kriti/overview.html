Kriti Bot: Reusable Enterprise AI Service

Built once. Reused across projects using YAML + JSON + URL configuration.

Kriti Bot is not a one-off chatbot. It is a reusable intelligence layer that plugs into any domain by changing schema manifests, declarative flows, and connection URLs, while keeping the orchestration core unchanged.

How New Deployments Happen

  1. Point to a new schema manifest JSON.
  2. Update business workflow YAML files.
  3. Set tenant DB URL and user context source.
  4. Deploy same engine; no feature branch per report.

How Bot Works (Implementation Reality)

Based on current code: FastAPI endpoints (`/chat`, `/health`, `/metrics`), LangGraph orchestration, SQL guardrails, deterministic fallbacks, and streaming NDJSON responses. 

graph TD
  U[User Request] --> API[POST /chat\nStreaming NDJSON]
  API --> R{RouterNode}

  R -->|CHAT| C[ChatNode\nPrompt Injection Checks\nGeneral Guidance]
  R -->|SQL| I[IntentNode]

  I --> SB[SQLBuilderNode\nIntent Detection + Filter Logic]
  SB --> V[SQLValidateNode\nSafety + Date Rewrite + Allowed Tables]
  V --> E[SQLExecuteNode\nDB Query Execution]
  E --> RES[ResponseNode\nFriendly Result Message]

  RES --> API
  C --> API

  CFG[(Reusable Config Layer\nYAML + JSON + URL)] -.-> SB
  CFG -.-> I
  CFG -.-> API

Efficiency and Token Model (Derived from Code Path)

SQL path usually invokes 2 LLM reasoning stages (`IntentService` + `IntentDetectionService`), and sometimes a 3rd (`build_select`) for explicit list requests. Chat path usually uses 1 LLM stage.
